# Gemini Code Assistant Project Context

This document provides context for the Gemini Code Assistant to understand the project and assist in its development.

## Project Overview

This project is a Visual Studio Code (VSCode) extension for the "QA Tool Orchestrator" (QATO). The extension's core idea is to provide a **Visual IDE for Karate**, allowing users to build tests with a rich user interface (Webview) rather than writing code directly.

Database and other custom logic are handled **out-of-process**. The test runner (Karate) communicates with helper services via standard protocols (HTTP), keeping the test runner clean from custom libraries.

## Final Implementation Plan

### 1. The VS Code Extension (Control Plane)

-   **Webview UI:** A rich user interface, likely built with React or Vue, that acts as a code generator for `.feature` files. Users build tests using visual forms and buttons.
-   **Extension Backend (TypeScript):**
    -   Manages the UI Webview.
    -   Securely stores connection credentials for different environments (e.g., Staging, Dev) using the `vscode.SecretStorage` API.
    -   Starts and stops a local "DB-Access Microservice" in the background when a test run begins.
    -   Executes the Karate JAR using the standard `java -jar` command.
    -   Presents the test results within the UI.

### 2. The DB-Access Microservice (Data Plane)

-   The `java-utils` project will be a tiny, standalone Spring Boot Java application.
-   It will expose **one primary API endpoint**: `POST /query`.
-   The request body will contain the SQL query and the target database type.
-   When started by the VS Code extension, it will be passed the secure credentials needed to connect to the target database.
-   Its sole responsibility is to execute the query and return the result as JSON.

### 3. The Karate Test (.feature file)

-   The `.feature` files generated by the UI will follow a clean, two-step process for database interaction:
    1.  Make an HTTP `POST` call to the DB-Access Microservice to run a SQL command.
    2.  Use the JSON response from the microservice in subsequent test steps.

## Key Technologies

*   **VSCode Extension Development:**
    *   **Language:** TypeScript
    *   **Framework:** VSCode Extension API
    *   **UI:** Webview (React/Vue)
*   **DB-Access Microservice:**
    *   **Language:** Java
    *   **Framework:** Spring Boot
*   **Testing:**
    *   **Test Runner:** Karate
    *   **Protocol:** HTTP

## How to Build and Test

### VSCode Extension

*   **Install dependencies:** `npm install`
*   **Build:** `npm run compile`
*   **Run tests:** `npm run test`

### DB-Access Microservice (Java)

*   **Build:** `mvn clean install` (from the `java-utils/qa-tool-orchaestrator` directory)
*   **Run:** The extension will manage the lifecycle of this service.
